# 日历订阅真机验收

自动化测试验证了 ICS 字节、解析往返与接口行为，但各日历客户端的刷新周期、提醒弹出和显示效果只能真机确认。按下面的顺序逐项打勾，记录客户端、系统版本与结果。

## 环境

- [ ] 服务通过有效 HTTPS 证书访问（生产域名），或在局域网调试时 `WEB_ORIGIN` 为电脑的局域网地址（仅限 HTTP 调试；日历客户端通常要求 HTTPS 才能订阅）。Google 日历、Outlook 由其服务端从公网拉取订阅地址，局域网地址不可用。
- [ ] 准备一个测试账号，不要用真实家人数据做破坏性测试。
- [ ] 记录：客户端 ______，系统版本 ______，设备 ______，账号时区 ______。

## 添加订阅

1. 网页「订阅」→「创建订阅地址」→ 在弹窗中填写订阅名称「我的手机」→「创建」→ 在列表中点「复制 HTTPS 地址」。
2. 按客户端添加订阅：
   - 苹果日历：「日历」App →「日历」→「添加日历」→「添加订阅日历」→ 粘贴地址 → 订阅；或在设备上打开网页，点「用日历 App 打开」（webcal 链接）。参考 [Apple 支持](https://support.apple.com/zh-cn/guide/iphone/iph3d1110d4/ios)。
   - Google 日历：仅电脑网页版支持，「其他日历」旁的 ＋ →「通过网址添加」→ 粘贴 HTTPS 地址。参考 [Google 日历帮助](https://support.google.com/calendar/answer/37100?hl=zh-Hans)。
   - Outlook 网页版：「添加日历」→「从 Web 中订阅」→ 粘贴 HTTPS 地址；首次同步与后续更新可能超过 24 小时。参考 [Microsoft 支持](https://support.microsoft.com/zh-cn/office/cff1429c-5af6-41ec-a5b4-74f2c278e98c)。

- [ ] 订阅成功，日历名称显示为「<显示名称>的纪念日」。
- [ ] 关闭页面再打开「订阅」，同一地址仍然完整显示，可以再次复制。

## 事件显示

为测试账号准备以下事件后，按客户端刷新：

- 苹果日历：在「日历」App 里下拉刷新，也可在 设置 → 日历 → 账户 → 已订阅的日历 调整「获取」频率。
- Google 日历、Outlook：由服务端定时拉取，不能手动刷新，等待更新后再核对。

## 提醒

- [ ] 「提前 1 天 09:00」的提醒在前一天 09:00（账号时区）弹出。
- [ ] 两条提醒都生效。
- [ ] 跨天事件只在开始日前提醒一次。
- [ ] 苹果日历：iPhone 设置 → 日历 → 已订阅的日历 →「移除提醒」关闭时提醒才会出现（iOS 默认可能移除订阅日历的提醒，需确认此开关）。

## 修改与同步

- [ ] 网页修改事件名称后，客户端刷新显示新标题，没有出现重复事件（UID 稳定）。
- [ ] 苹果日历、Google 日历：把纪念日的重复规则从每月改为每 2 周后刷新，旧规则的条目全部消失、只剩新规则的条目。旧条目没有消失时立即停止验收并报告，不要自行加 CANCELLED 或墓碑。
- [ ] 删除事件后，刷新后从客户端消失。
- [ ] 新增事件后，刷新后出现。
- [ ] 订阅地址保持不变，不需要重新添加。

## 撤销与轮换

- [ ] 网页「轮换」后，旧订阅刷新失败或停止更新；用新地址重新添加可用。
- [ ] 网页「撤销」后，客户端上的订阅停止更新。
- [ ] 管理员停用该账号后，订阅停止更新。
