# 纪念日规则

所有规则在 `packages/calendar` 实现，网页预览、订阅输出和备份校验调用同一份代码；`tests/calendar/` 锁定了下面每一条。

## 事件类型

| 类型     | 标题默认模板（已知年份 / 年份未知）            | 重复       |
| -------- | ---------------------------------------------- | ---------- |
| 生日     | `{{name}} {{years}} 岁生日` / `{{name}}生日`   | 每年       |
| 纪念日   | `{{name}}第 {{years}} 周年` / `{{name}}纪念日` | 见重复规则 |
| 普通事件 | `{{name}}`                                     | 只发生一次 |

- `{{years}}` = 逻辑年份 − 原始年份，从 1 开始；不生成第 0 周年或原始日期之前的年份。
- 年份未知时每年都生成，模板不能使用 `{{years}}`；表单切换「年份未知」时默认模板自动切换，自定义模板保持不变。
- 普通事件必须是公历且填写年份，不能使用 `{{years}}`；它只输出保存的那一次，不受订阅窗口影响。
- 标题前缀（如 🎂）幂等：渲染结果已以前缀开头时不重复添加；前缀与标题之间加一个空格。
- 模板变量为白名单：`{{name}}` 总可用；`{{years}}` 只在「每 1 年」且年份已知时可用；`{{count}}`（第几次，即周期序号 k）只用于纪念日非「每 1 年」且年份已知；`{{days}}` 只用于里程碑标题模板。其他花括号一律拒绝。

## 公历

每个逻辑年份取同月同日。原始日期是 2 月 29 日时，平年按事件的规则：

| 规则（`rules.feb29`） | 平年的发生日 |
| --------------------- | ------------ |
| `feb28`（默认）       | 2 月 28 日   |
| `mar1`                | 3 月 1 日    |
| `skip`                | 不生成       |

闰年保持 2 月 29 日。

## 农历

农历原始日期以「农历年 + 月 + 日 + 是否闰月」保存，每个目标农历年单独换算为公历（lunar-typescript）。逻辑年份是农历年，所以腊月的生日会落在下一个公历年初：例如 1990 年腊月廿九出生，农历 2025 年的生日是公历 2026-02-16，显示 35 岁。

**闰月原始日期**（`rules.leapMonth`）：目标年份有同一个闰月时用闰月；没有时——

| 规则              | 处理             |
| ----------------- | ---------------- |
| `regular`（默认） | 使用同名的普通月 |
| `skip`            | 当年不生成       |

**三十**（`rules.missingDay`，只用于农历；公历按月重复的缺日见「重复规则」的 `gregorianMissingDay`）：农历小月只有 29 天。原始日期是三十而目标月只有 29 天时——

| 规则              | 处理                   |
| ----------------- | ---------------------- |
| `lastDay`（默认） | 取该月最后一天（廿九） |
| `skip`            | 当年不生成             |

**支持范围**：农历 1900–2100 年。已知年份的原始日期会校验真实存在（例如「2025 年闰二月」不存在会定位到闰月字段），超出范围时给出可见错误，不静默算错。表单从公历切换为农历依据时，会把已填的公历日期换算成农历并提示核对。

## 重复规则

生日、普通事件和年份未知的事件固定为「每 1 年、永不结束」。纪念日可以设置 `recurrence = { unit, interval, end }`：

- 单位 `day`/`week`/`month`/`year`，间隔上限 999/99/99/99（`maxInterval`）；农历只能按年。
- 起始日为第 0 次，从第 1 次开始输出；每一次都从起始日直接推算：按天/周为起始日 + k × 间隔 ×（1 或 7）天，按月为起始年月 + k × 间隔个月、日取原始日。按年沿用上面的周年逻辑，只取间隔的倍数年，2 月 29 日仍按 `rules.feb29`。
- 公历按月遇到当月没有原始日（`gregorianMissingDay`）：`lastDay`（默认）落到月末，`skip` 跳过这一次。例如 1/31 每月：2/28（闰年 2/29）、3/31、4/30；11/30 每 3 个月：2/28、5/30。
- 结束条件：永不；共 N 个周期（1–999，按周期序号计，被跳过的那次也占序号）；截止到某天（开始日 ≤ 截止日就输出，农历先换算成公历开始日再比较，持续天数不截断）。
- 按天/周/月时持续天数不超过一个最短周期（1/7/28 天），提醒提前天数小于该值。

默认标题（仍是默认模板时随规则自动切换）：隔 N 年「`{{name}}第 {{count}} 次`」，每周「`{{name}}第 {{count}} 周`」，每月「`{{name}}第 {{count}} 个月`」，其余「`{{name}}第 {{count}} 次`」。

## 里程碑

纪念日（年份已知）可设最多 20 个里程碑天数（1–36500）：第 N 天 = 起始日 + N 天，起始日为第 0 天，农历先换算成公历起点。里程碑不受结束条件和缺日规则影响，持续 1 天，沿用事件的提醒，标题用 `milestoneTemplate`（默认「`{{name}}第 {{days}} 天`」）。

## 跨天事件

`durationDays` 为 1–366 天（普通事件在表单中以「最后一天」填写）。ICS 中为全天事件，`DTEND` 是排他结束日：10/1 起 7 天输出 `DTSTART:20261001`、`DTEND:20261008`；12/30 起 5 天跨越公历年，`DTEND:20270104`。

## 提醒

每个事件最多两条提醒，每条为「提前 N 天（0–365）+ 本地时刻 HH:mm」。时刻按**账号时区**（IANA）换算成绝对 UTC，写入 `TRIGGER;VALUE=DATE-TIME:…Z`：

- 上海时区、提前 1 天 09:00：2026-02-16 的事件 → `20260215T010000Z`。
- 夏令时跳过的本地时刻顺延到跳变之后：纽约 2026-03-08 的 02:30 → 03:30 EDT（`07:30Z`）。
- 夏令时重复出现的本地时刻取较早的一次：纽约 2026-11-01 的 01:30 → EDT（`05:30Z`）。

跨天事件只在开始日前提醒。修改账号时区会改变所有提醒的 UTC 时间（订阅刷新后生效）。

## 订阅窗口

按账号时区的「今年」计算：输出过去 `FEED_WINDOW_PAST_YEARS`（默认 1）年到未来 `FEED_WINDOW_FUTURE_YEARS`（默认 20）年的逻辑年份；跨年时窗口自动滚动，最早一年移出、最晚一年加入。

- 每一次都是独立的 VEVENT，不写 RRULE。UID：按年 `{id}-{逻辑年份}@timenote`，按天/周/月 `{id}-k{序号}@timenote`，里程碑 `{id}-m{天数}@timenote`，普通事件 `{id}@timenote`；窗口滑动时同一次的 UID 不变。
- 按天/周/月在窗口内以今天为界，每个事件最多输出过去 12 次、未来 60 次；里程碑在窗口内全部输出。
- 修改事件后 revision + 1，SEQUENCE 随之递增；规则改了以后旧 UID 不再出现，不输出 CANCELLED 或墓碑。
- 总量上限：每个账号 Σ（非按年重复事件计 72 + 里程碑个数）≤ 15000，保存和备份导入时检查，超出返回 `RECURRENCE_LIMIT`（HTTP 422），备份整份拒绝；订阅输出本身不设上限。

## 「未来 5 次」预览

从账号时区的今天起，找最近 5 次「最后一天 ≥ 今天」的发生（仍在持续中的那一次也算），里程碑按日期混排。2 月 29 日跳过规则最多每 8 年才发生一次，搜索范围足以凑满 5 次。普通事件始终显示它唯一的那一次，即使已经过去。
