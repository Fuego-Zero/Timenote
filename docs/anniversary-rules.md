# 纪念日规则

所有规则在 `packages/calendar` 实现，网页预览、订阅输出和备份校验调用同一份代码；`tests/calendar/` 锁定了下面每一条。

## 事件类型

| 类型     | 标题默认模板（已知年份 / 年份未知）            | 重复       |
| -------- | ---------------------------------------------- | ---------- |
| 生日     | `{{name}} {{years}} 岁生日` / `{{name}}生日`   | 每年       |
| 纪念日   | `{{name}}第 {{years}} 周年` / `{{name}}纪念日` | 每年       |
| 普通事件 | `{{name}}`                                     | 只发生一次 |

- `{{years}}` = 逻辑年份 − 原始年份，从 1 开始；不生成第 0 周年或原始日期之前的年份。
- 年份未知时每年都生成，模板不能使用 `{{years}}`；表单切换「年份未知」时默认模板自动切换，自定义模板保持不变。
- 普通事件必须是公历且填写年份，不能使用 `{{years}}`；它只输出保存的那一次，不受订阅窗口影响。
- 标题前缀（如 🎂）幂等：渲染结果已以前缀开头时不重复添加；前缀与标题之间加一个空格。
- 模板只允许 `{{name}}` 与 `{{years}}`，其他花括号一律拒绝。

## 公历

每个逻辑年份取同月同日。原始日期是 2 月 29 日时，平年按事件的规则：

| 规则（`rules.feb29`） | 平年的发生日 |
| --------------------- | ------------ |
| `feb28`（默认）       | 2 月 28 日   |
| `mar1`                | 3 月 1 日    |
| `skip`                | 不生成       |

闰年保持 2 月 29 日。

## 农历

农历原始日期以「农历年 + 月 + 日 + 是否闰月」保存，每个目标农历年单独换算为公历（lunar-typescript）。逻辑年份是农历年，所以腊月的生日会落在下一个公历年初：例如 1990 年腊月廿九出生，农历 2025 年的生日是公历 2026-02-16，显示 35 岁。

**闰月原始日期**（`rules.leapMonth`）：目标年份有同一个闰月时用闰月；没有时——

| 规则              | 处理             |
| ----------------- | ---------------- |
| `regular`（默认） | 使用同名的普通月 |
| `skip`            | 当年不生成       |

**三十**（`rules.missingDay`）：农历小月只有 29 天。原始日期是三十而目标月只有 29 天时——

| 规则              | 处理                   |
| ----------------- | ---------------------- |
| `lastDay`（默认） | 取该月最后一天（廿九） |
| `skip`            | 当年不生成             |

**支持范围**：农历 1900–2100 年。已知年份的原始日期会校验真实存在（例如「2025 年闰二月」不存在会定位到闰月字段），超出范围时给出可见错误，不静默算错。表单从公历切换为农历依据时，会把已填的公历日期换算成农历并提示核对。

## 跨天事件

`durationDays` 为 1–366 天（普通事件在表单中以「最后一天」填写）。ICS 中为全天事件，`DTEND` 是排他结束日：10/1 起 7 天输出 `DTSTART:20261001`、`DTEND:20261008`；12/30 起 5 天跨越公历年，`DTEND:20270104`。

## 提醒

每个事件最多两条提醒，每条为「提前 N 天（0–365）+ 本地时刻 HH:mm」。时刻按**账号时区**（IANA）换算成绝对 UTC，写入 `TRIGGER;VALUE=DATE-TIME:…Z`：

- 上海时区、提前 1 天 09:00：2026-02-16 的事件 → `20260215T010000Z`。
- 夏令时跳过的本地时刻顺延到跳变之后：纽约 2026-03-08 的 02:30 → 03:30 EDT（`07:30Z`）。
- 夏令时重复出现的本地时刻取较早的一次：纽约 2026-11-01 的 01:30 → EDT（`05:30Z`）。

跨天事件只在开始日前提醒。修改账号时区会改变所有提醒的 UTC 时间（订阅刷新后生效）。

## 订阅窗口

按账号时区的「今年」计算：输出过去 `FEED_WINDOW_PAST_YEARS`（默认 1）年到未来 `FEED_WINDOW_FUTURE_YEARS`（默认 20）年的逻辑年份；跨年时窗口自动滚动，最早一年移出、最晚一年加入。

## 「未来 5 次」预览

从账号时区的今天起，找最近 5 次「最后一天 ≥ 今天」的发生（仍在持续中的那一次也算）。2 月 29 日跳过规则最多每 8 年才发生一次，搜索范围足以凑满 5 次。普通事件始终显示它唯一的那一次，即使已经过去。
